# Лабораторная работа №2. Модульное тестирование

## Описание задачи

Цель — получить навыки автоматизации модульного тестирования средствами среды разработки. Работа выполнена на Python с использованием стандартного модуля `unittest`, внешние библиотеки не подключались.

Разработаны два класса и наборы модульных тестов к ним:

1) `LCMCalc` — нахождение наименьшего общего кратного (вариант №4).
2) `Stack` — стек, структура данных LIFO (собственный класс, вариант №5).

## Что реализовано

1) Класс `LCMCalc` с тремя методами: НОД двух чисел, НОК двух чисел, НОК для списка чисел.
2) Класс `Stack` с полным набором операций над стеком.
3) Полная валидация входных данных в обоих классах: проверка типа, диапазона, размера, недопустимых значений.
4) Два независимых набора модульных тестов: 33 теста для `LCMCalc` и 25 тестов для `Stack`.
5) Поэтапный вывод для каждого теста: описание проверки, ожидаемое значение, фактическое значение.
6) Проверка негативных сценариев через `assertRaises` — с явным указанием ожидаемого типа исключения.

## Файлы лабораторной №2

1) `lcm_4.py` — реализация класса НОК.

## Класс LCMCalc (НОК)

Формула: НОК(a, b) = |a * b| / НОД(a, b).

Методы класса:

1) `gcd(first, second)` — НОД двух чисел (алгоритм Евклида).
2) `lcm_two(first, second)` — НОК двух чисел.
3) `lcm_list(numbers)` — НОК для списка чисел.

Что отклоняется с исключением:

1) Нецелые аргументы: `float`, `str`, `None`, `bool`, `complex`, `list` → `TypeError`.
2) Нуль как аргумент (НОК с нулём математически не определён) → `ValueError`.
3) Пустой список → `ValueError`.
4) Слишком длинный список (> `MAX_LIST_SIZE`) → `ValueError`.
5) Числа, чей модуль больше `MAX_VALUE` → `ValueError`.
6) Не-список вместо списка (`None`, `str`, `tuple`, `int`) → `TypeError`.

Отрицательные числа допускаются: результат берётся по модулю, так как НОК по определению неотрицателен.

## Класс Stack (стек)

Структура данных работает по принципу LIFO — последний пришёл, первый вышел.

Методы класса:

1) `push(item)` — положить элемент наверх.
2) `pop()` — снять и вернуть верхний элемент.
3) `peek()` — посмотреть верхний элемент без снятия.
4) `is_empty()` — проверить, пуст ли стек.
5) `size()` — получить количество элементов.
6) `clear()` — полностью очистить стек.
7) `__len__` — поддержка встроенной функции `len(stack)`.
8) `__str__` — удобное представление через `print(stack)`.

Что отклоняется с исключением:

1) `pop` на пустом стеке → `IndexError`.
2) `peek` на пустом стеке → `IndexError`.
3) `push` при переполнении (> `MAX_SIZE`) → `OverflowError`.
4) `push` без аргумента или с лишними аргументами → `TypeError` (стандартное поведение Python).

Стек принимает значения любого типа: `int`, `float`, `str`, `None`, `list` и другие.

## Что проверяют тесты

Для каждого класса покрыты четыре категории сценариев:

1) Нормальные — обычные данные и ожидаемый результат.
2) Граничные — пустой стек, список из одного элемента, ноль, стек на пределе, одиночный отрицательный элемент.
3) Негативные — неправильный тип данных, недопустимое значение, выход за предел, пустой список.
4) Согласованность — операции не портят объект (например, `peek` не меняет размер, повторный `peek` возвращает тот же элемент).

Все проверки оформлены через `assertEqual`, `assertTrue`, `assertFalse` и `assertRaises`. Каждый тест печатает описание, ожидаемое и фактическое значение — это упрощает ручную проверку и разбор ошибок при отладке.
